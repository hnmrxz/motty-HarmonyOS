## 2. 剩余缺口分级

| 级别 | 项 | 成本 | 备注 |
|---|---|---|---|
| **P0** | 每次改动后的定向回归（`--only`） | 5–15 分钟 | 已支持 |
| **P0** | 里程碑全量（`--quick` 12 条 / 全量） | 12 分钟 / 80 分钟 | 每 5~10 轮一次全量 |
| **P1** | 主机表单/详情补「协议参数」（RDP 分辨率等） | 中 | 需 C++ 侧支持才能真正生效，避免"只存不用" |

| **P2** | ProxyJump 跳板 | 大 | libssh2 无可插拔 transport，需自建 socket 抽象 |
| **P2** | arm64 真机验证 | 需硬件 | 保持 E3 记录，不阻塞 |
| **P3** | 平板形态 | 暂停 | 按目标要求 |

**结论**：P0 是提速手段；P1/P2 才是功能。当前优先把 P0 流程固化，再决定是否投入 P1 大改。

## 3. 提速规则（每轮照着做）

1. **模拟器常驻**：只在必要时启动一次；卡死才重启（重启要 1–2 分钟且拖慢整机）。
2. **改动即定向回归**：
   ```powershell
   $env:MOTTY_RUN_ID="r<round>-<tag>"
   python harmonyos\tools\run-all.py --only <spec 前缀>
   ```
3. **多前缀合并**：`--only host` 跑全部主机类；宁可一次跑 5 条，也不要分 5 次。
4. **里程碑才全量**：每 5~10 轮跑一次；出问题用 `--resume` 续跑，不重跑已过的。
5. **静态优先**：UI 只加文字/id/布局的改动，先 build + `spec/lint.py` 保证 E2，
   再选 1 条代表用例做 E1，不为此写新用例。
6. **不为"能存不能用"的配置写代码**：宁可留缺口，也不加假功能。
7. **文档一次写清**：每轮在 `UI-PARITY.md` 追加 5~10 行，避免反复重写整篇。

## 4. 每轮标准动作（约 10–20 分钟）

```
build → install -r → run-all --only <tag> → git commit → push → hiboard_push
```
只在 `--quick`（12 条）或全量（92 条）失败时才排查细节。

## 5. 收尾顺序（建议）

1. 用 `--quick` 确认当前 92 条基线（约 12 分钟，一次）。
2. 把 P1「协议参数」拆成"先只做 UI + 明确标注未生效"？**不做**——按规则 6，跳过。
3. 评估 P1「RDP 常驻会话」：若要做，单独开一轮只改 C++，用 `rdp.client-render` +
   `rdp.session-view` 两条用例验证，不跑全量。
4. 最后更新 README/REGRESSION 基线到最终数字，结项。

## 6. 不再做的事

- 每轮全量跑批（80 分钟/次）。
- 反复重启模拟器。
- 为同一功能写多份重复文档。
- 追求"字段对齐"式的装饰性改动。
