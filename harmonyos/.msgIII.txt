docs(harmonyos/rdp): 三次改预览入口三次破坏布局 —— 记录根因并回退到 3/3

本轮想做的事: 把 rdp.preview(点按钮->写BMP->Image显示)做成独立入口+独立用例, 不干扰原有三条 RDP 用例

实际发生:
1. 按钮追加到已有按钮 Row -> 该行变宽, 后续按钮被挤/裁, 原有用例点不到 rdp/render、rdp/input
2. 按钮放到 "rdp/srv-start 按钮的 .onClick 之后" -> 代码插进 onClick 闭包里(那不是 UI), 按钮根本不渲染
   -> 用例报"选择器未命中 rdp/frame-btn"
3. 按钮改成独立 Row 插在按钮行之前 -> 破坏该 @Builder 结构, 连 rdp/srv-start 都找不到
三次都回退, 代码恢复 r47 状态, 3/3 用例恢复 PASS

根因(真正的收获): Index.ets 近 3000 行单文件, UI 全在 build()/@Builder 里, 一直用字符串/行号锚点插入
- 锚点行在 onClick 闭包里时, 插入的 UI 不会渲染
- 插在 Row/Column 结构中间时, 会改变其它元素布局, 导致别的用例点击坐标失效
=> 加 UI 必须先看清所在闭包与容器, 新 UI 放新的独立容器, 插完立刻用小用例(截图+节点 dump)
   验证"自己在新位置可见"且"原有按钮仍在原位"

现状: 回退后 rdp.server-peer / rdp.client-render / rdp.client-input => 3/3 PASS, lint 全绿
RDP 画面显示能力(BMP 路线)仍已被手工证明可用(见 Round 48 截图), 但还没有稳定的机器可判入口

下一轮做法(不再用行号锚点): 整体重写诊断面板 RDP 区块一小段(明确 Container + 一行按钮 + 预览图),
重写后先 dump 确认三个 id 都在且坐标不重叠, 再写 rdp.preview 用例
