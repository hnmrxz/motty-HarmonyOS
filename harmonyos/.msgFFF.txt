docs(harmonyos/rdp): 把已解码画面接到 UI 的方案(依据官方 PixelMap 文档) + 全量回归 full46 启动

现状: 客户端已能把 32bpp 压缩位图用 planar_decompress 解到自建帧缓冲, 64x48 采样 1377 色
  但还没接到产品界面: 现在只有诊断面板里 64x48 的采样图

为什么不逐像素画: fillRect 逐像素 = 786432 次调用, ARK UI 会卡死, 必须走位图对象

方案(依据 devecocli docs search "PixelMap createPixelMap" 命中的官方指南与 pixelmap_native.h):
- ArkTS: image.createPixelMap(buffer, {size, srcPixelFormat, pixelFormat}) 可直接从 ArrayBuffer 建像素图,
  再 Image(pixelMap) 渲染
- NAPI: 只需把 g_frame(RGBA32, 1024x768x4 = 3MB) 拷成 ArrayBuffer 返回

三步落地:
1. mottynapi.rdpFrame() 返回 {width, height, buffer}(复用缓冲避免每帧分配)
2. startRdpRender 回调里 createPixelMap 存 @State rdpPixel, 界面 Image(this.rdpPixel)
3. 用例断言"像素图尺寸=1024x768 且非纯白"(用节点尺寸+采样统计, 不靠肉眼看截图)

风险与边界: 3MB 拷贝 x 多帧有内存/GC 压力, 需降频或只在变化时拷贝; PixelMap 失败要降级回 64x48 采样图;
  全部需要 PC(2in1) 实测, 不能凭 API 文档声称可用
