feat(harmonyos/rdp): 增量判断(帧没变不写 3MB) + 发现真实 UI 缺陷(srv-stop 点不到)

实现:
- C++ g_frameSeq 每次解压成功后 +1, NAPI rdpFrameSeq() 暴露
- updateRdpFrame 先比对序号: 与上次相同 -> skipped++, 不写文件不换图
- 文案: bmp: 1024x768 written writes=N / bmp: skip unchanged writes=N skipped=M

用例:
- rdp.preview 覆盖"预览按钮触发写入并持续刷新"(写入或跳过都算在跑) PASS
- rdp.preview-idle(新) 覆盖"渲染结束客户端断开后帧序号冻结 -> skipped 增长" PASS
回归: rdp.server-peer / rdp.client-render / rdp.client-input => 3/3 PASS (RDP 相关共 5 条)

发现的真实 UI 缺陷(待修): 想用 rdp/srv-stop 停服务端制造帧冻结, 结果点不到 —— dump 里没有这个 id
  它和 rdp/srv-status、rdp/nla、rdp/pass 一起被按钮行/输入行溢出裁掉(同行元素太多, 超出 680 宽面板)
  这是产品级问题: 停止服务端的按钮用户根本点不到
  处置: 用例改成"渲染结束后帧自然冻结"等价场景; UI 缺陷单独记录, 下一轮移到独立行

教训: 用例断言要跟实现一起演进; 加了"跳过"后原来只认 written 的断言会误报
  改成同时接受 written 与 skip 两种文案
