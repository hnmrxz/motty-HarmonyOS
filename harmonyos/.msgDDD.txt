feat(harmonyos/rdp): 自解码成功 —— 32bpp 压缩位图必须走 planar_decompress(GDI 靠不住)

关键发现(解释之前所有白屏): FreeRDP 自己在 gdi/graphics.c:gdi_Bitmap_Decompress 里分派
  bpp < 32  -> interleaved_decompress
  bpp == 32 -> planar_decompress
我们的环境是 32bpp, 只调 interleaved -> ilv=0/163 全失败; 改用 planar_decompress -> planar=163/0(163成功/0失败)
这也解释了 gdi_bitmap_update 为何不写主缓冲: 它内部同样解 32bpp 压缩位图, 解不开就静默跳过

现在实现: OnBitmapUpdate 自己解压到自建帧缓冲 g_frame(RGBA32, 1024x768)
  bpp>=32 且 compressed -> planar_decompress(vFlip=TRUE)
  bpp<32 且 compressed -> interleaved_decompress
  未压缩 -> 按行把 BGR 拷成 RGBA
快照 snapshotFromGdi 改为优先读自解码帧缓冲(GDI 主缓冲兜底)

并发问题(已修): 自解码跑通后 rdp.client-input 又把进程搞崩(ps=0),
  原因: 位图解码在内部线程、快照在 EndPaint 线程, 并发读写 g_frame 与解码上下文
  加 g_frameMtx 后: rdp.client-input PASS / rdp.client-render PASS / rdp.server-peer PASS
  教训: 自己加的共享缓冲, 一上手就要锁

还没验证: planar=163/0 只证明解压函数返回成功, 不等于像素正确
